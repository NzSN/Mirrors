## Implemented build behavior

The checked-in Python 3.10 host identity has been removed. Lake now prepares
`Shell.Dpm.HostIdentity` under `.lake/build/dpm-generated` before compiling its
importers. It runs `python3` from the build's `PATH`, or the explicit
`MIRRORS_DPM_PYTHON`, with isolation flags. The generator resolves and hashes
that interpreter and the packaged host sources. Generated bytes change only
when those inputs change; ordinary builds do not rewrite tracked helper pins.
Stale installer helper pins require an explicit reviewed helper refresh.

The runtime still checks every packaged helper and the exact interpreter before
executing Python. An installed launcher remains bound to that path and hash.
The build-time environment variable is not a runtime override. Ordinary
`lake build mirror` has no DPM Python dependency. See the
[CLI prerequisites](../../Docs/dpm-cli-guide.md#build-and-runtime-prerequisites).

## Existing temporary-directory limitation

`Shell/Apalache/SpecSource.lean` retains a trailing slash from `TMPDIR` and adds
another separator. With `/tmp/`, it records `/tmp//modelmirrors-session-…`, while
the synthetic Bash fixture prints canonical `$PWD` as
`/tmp/modelmirrors-session-…`. `Shell/Apalache/Cli.lean` replaces only the literal
recorded directory, so the error can retain the canonical path.

The relevant runtime, test and fixture files match the baseline. The baseline
was separately archived and rebuilt before running both environment controls.
This task leaves that runtime behavior unchanged. The passing command is:

```sh
TMPDIR=/tmp bash tools/run-local-no-model-check.sh
```

This environment selection is a validation condition, not a sanitizer fix or
a claim that the inherited environment passes. Normalize/sanitize equivalent
temporary-root spellings in separate runtime work.
