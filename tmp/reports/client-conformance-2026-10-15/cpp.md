# MirrorCPP client-guide audit — 2026-10-15

**One confirmed P2 gap in the optional Gate acceptance integration; no confirmed base-wire or compiled-verification safety violation found in this source audit.**

The [factory error wrapper](/home/nzsn/Repos/MirrorCPP/src/client.cpp:382) replaces all returned factory errors with `adapter_factory_failed`. The [Gate seam](/home/nzsn/Repos/MirrorGate/integrations/mirrorcpp/orchestration.cpp:164) intentionally returns typed `mirrorgate.<code>` errors from authorization, backend admission and worker attachment; those identities are discarded. The generated binding additionally maps worker invoke/observe `SdkError` exceptions into `adapter_failure` or `observation_shape_mismatch`. Thus native facade callers cannot reliably distinguish admission, transport/protocol, deadline/cancellation and application failures, contrary to SO7. The core Gate SDK preserves these families. `Error` has no structured cause field, `SdkError::what()` contains only the supplied human message, and `SandboxEvidence` stores no original failure; the lost code cannot be recovered from another result field. No isolation bypass or successful-conformance false positive was established.

Smallest fix: retain original trusted Gate error code/stage at the orchestration boundary and restore it when returning the facade result; keep model mismatch and primary-over-cleanup priority. Avoid treating arbitrary application exceptions as trusted mechanical errors. Add remote-only negative fixtures for backend denial, bad worker handshake, worker deadline and application failure. This finding is confirmed by source control flow; a fresh runtime reproduction was proposed to the coordinator.

**C5 needs a guide clarification.** Async `register_error` intentionally leaves the borrowed connection open ([source](/home/nzsn/Repos/MirrorCPP/src/client.cpp:830)). C5 says use a new connection after `register_error`, while section 10 says terminal for that register attempt. Closing the submitter would cancel/evict its earlier jobs; resolve that documentation ambiguity before changing this behavior. It is not included as a confirmed runtime defect.
