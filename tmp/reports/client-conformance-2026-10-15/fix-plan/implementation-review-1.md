## Behavior boundaries checked

- **Lean TLS and key admission:** `MirrorLean/ServerMode.lean` rejects an empty effective identity before calling the native entry point. The C guard independently rejects null/empty names before credentials, SSL allocation, DNS or sockets. Existing DNS/IP SAN setup is unconditional after that guard; pin checking remains additive. Exact low-07777 key comparison precedes credential loading and does not change caller files. Native tests cover the public and raw Lean entry, missing-credential precedence, observed zero accepts, SAN/CN/pin controls, valid mTLS and exact mode readbacks. The native null-pointer branch is source evidence; the raw Lean runtime case supplies an empty string.
- **Lean source closure:** string mode consumes escapes without interpreting comment markers; nested comments preserve newlines and a separator; the later tokenizer still ignores quoted tokens. The resolver continues returning original source text in root-first order. New tests cover original marker failure, false quoted dependencies, token boundaries, real missing dependencies, shared/cyclic closure and final encoded-byte admission separately from discovery.
- **Lean nullable follow-up:** the shared optional-string helper now maps explicit null to absence while retaining malformed-present-value rejection. Inspected uses include config optionals, trace view and mismatch action. Typed outgoing omission is unchanged. This remains the separate convenience-decoder follow-up, not a claim that default numeric/string options or normal typed output were broken.
- **ECMA compiled admission:** one pure target/contract predicate is shared by callback, explicit sync and explicit async preparation. Supported target/contract pairs and target-versus-contract error codes match the approved plan. Invalid pairs fail before registry resolution and transport acquisition; descriptor selections retain their target-neutral preparation/acquisition path. Tests exercise void/report, generated/precomputed and spawn paths, exact invalid-key registration, zero side effects, async-v1/v2 success and descriptor sync/async integration.
- **ECMA POSIX keys:** exact low-07777 admission is before CA/certificate/key reads and TLS connect. The new test uses valid credentials and actual mTLS for the normal path, checks zero network acquisition plus missing-credential precedence for invalid modes, and retains caller key bytes/modes.
- **Mirrors framing:** stdio rejects nonempty EOF without LF. TCP/TLS distinguish error sentinels from clean EOF, discard the failed fragment and reject syntactically complete unterminated JSON. Complete buffered frames are delivered before a later socket read; CRLF, existing byte bounds and UTF-8 validation remain in place. Maintained tests include bounded actual CLI TCP/TLS/stdio peers, exact byte limits, split multibyte input, TLS close-notify versus abrupt close, reset, no successful validation/capture after invalid framing and child/thread cleanup.
- **Mirrors async continuation:** explicit async submission/job-control arms retain their existing continuation; every delegated synchronous/default dispatch returns false. Thus idle-phase failure cannot reopen the connection. New finite scripted JobStore input covers recoverable bound/capacity rejection, successful/failed synchronous completion, malformed/unexpected/replay failures, no queued-request dispatch, owner eviction and other-owner survival. A blocking fake job is released in `finally`; session cancellation/eviction does not wait for that fake body before the release.
- **Mirrors trace cancellation:** only the private poll-budget-exhausted variant invokes best-effort cancellation. Peer/protocol/transport errors, wrong correlation/result kind and terminal job outcomes return without follow-up writes. Public result/primary diagnostic remain stable. Tests cover exact full write sequences, zero/positive budgets, throwing receive, terminal replies, EOF and cancellation-send failure; actual CLI failures also retain no-publication assertions.
- **Maintained drivers:** the new framing gate is wired into both Lake's driver and the non-model shell driver. Test fixtures do not invoke model operations. Existing full-driver/live-path restrictions and remote-only execution still apply.
