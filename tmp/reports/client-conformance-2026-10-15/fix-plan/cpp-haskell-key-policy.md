## F4 — preserve Gate failure origin through C++ orchestration

**Scope and evidence.** The optional Gate-owned fixture is `MirrorGate/integrations/mirrorcpp`, not an advertised released generic MirrorCPP Gate package. SO7 requires distinct control compatibility, admission, build, negotiation, worker transport/protocol, application, timeout/cancellation and Mirrors mismatch families; SO8 and the guide's `finish` equations require body failure to win over cleanup failure.

The audited public-runner probe reproduced code collapse with FakeTransport and three classified factory results, not an actual Gate process. Current source confirms:

- `MirrorCPP/src/client.cpp:382` maps factory failures to `adapter_factory_failed`; `dispose_binding` maps disposal failures to `adapter_dispose_failed`. Callback exception handling preserves only `ModelInterfaceBindingError.code()` or emits generic adapter codes.
- `Mirrors/Shell/ModelInterface/Emit/Cpp.lean:664` emits broad callback catches. The checked generated Counter header at `MirrorCPP/test/fixtures/model-interface/counter/generated/CounterMirror.generated.hpp:323` maps invoke failures to `adapter_failure` and observe failures to `observation_shape_mismatch`.
- `MirrorGate/integrations/mirrorcpp/orchestration.cpp:11` converts `SdkError` into `Error.code = mirrorgate.<code>` but drops `stage` and `operation_id`; the public runner subsequently normalizes the factory error. `SandboxEvidence` currently records cleanup and counters only.
- `MirrorGate/sdk/cpp/src/managed_worker.cpp:538` already remembers the first `SdkError`, including code, stage and operation ID, in private `primary_error_`. It is not publicly inspectable. The worker records normal invoke/observe call failures before the generated binding catches them; `close` can also record a cleanup-only failure later.

**Recommended minimal intervention: Gate-owned structured capture.** Preserve failure information in the trusted integration and SDK. Keep MirrorCPP's generic adapter classification and compiler-generated callback normalization unchanged.

1. In `MirrorGate/sdk/cpp/include/mirrorgate/managed_worker.hpp` and `sdk/cpp/src/managed_worker.cpp`, add a const accessor returning an owned optional failure snapshot. Do not expose a mutable pointer/reference to `primary_error_`. Snapshot fields: SDK-assigned origin/family, exact original code and stage, operation ID, and bounded diagnostic text. Keep the original SDK stage unchanged even when empty; use a distinct trusted operation field such as attach/invoke/observe for local context.
2. Ensure the first snapshot is set at the trusted failure site, before generated callback catches run. Cover call/receive/decode errors, attachment and public invoke/observe precondition or input-encoding failures; the latter currently occur outside some `remember_primary` catches. This is diagnostics capture, not a second teardown controller.
3. In `integrations/mirrorcpp/orchestration.hpp/.cpp`, add first-primary and secondary-cleanup structured evidence. Capture preparation/authorization/acquire/attach `SdkError` at their existing trusted catches, including failures before a `LocalBinding` exists. After acquisition, keep the relevant worker reachable by the facade's capture state. For a failed `bind_worker` result, snapshot it before closing the worker.
4. Wrap the binding's existing `dispose` callback as it is wrapped today, but snapshot the worker's body failure **before** invoking generated disposal or `ManagedWorker::close`. This is the concrete attachment point that recovers invoke/observe failures: the public runner disposes after a callback fails, and the SDK already retained the original failure. Then collect cleanup diagnostics separately. Never promote a failure first observed during disposal into a body failure.
5. When the runner returns its normalized adapter error for an operation with a captured trusted body failure, the facade returns the corresponding Gate-classified `Error`, retaining exact code/stage in `SandboxEvidence`. Preserve ordinary model negotiation errors and `step_mismatch` with expected/actual/hints. Promote cleanup failure only after body success. Preserve body error when cleanup also fails, including unconfirmed control shutdown, and retain both structured records in evidence.
6. Update the integration's trusted failure summary to use the recorded family instead of reducing every Gate failure to `ErrorKind::model_interface`. Preserve existing cleanup ownership and attached-daemon isolation rules.

**Classification authority must be explicit.** Do not infer families by parsing human messages, accepting a caller's arbitrary `Error.code`, or assuming every `SdkError.code` is host-authored. `managed_worker.cpp:461` currently constructs an `SdkError` directly from a worker reply's code after syntax validation. Those application-authored codes need an SDK-assigned `worker_application` origin; retain the original value as diagnostic data, without allowing a worker-provided string such as `BACKEND_ADMISSION_FAILED` to acquire control/admission authority. In contrast, `sdk/cpp/src/control.cpp:58` validates known control codes/stages from the trusted supervisor. Locally detected framing/protocol/deadline/cancel events receive their origin from SDK control flow. Avoid classifying ordinary arbitrary adapter exceptions as Gate errors. A spoofed worker error code needs a regression control; this is a design constraint identified while planning, not a newly runtime-confirmed audit finding. If the current worker retry loop treats a peer-authored `DEADLINE_EXCEEDED` as a local read timeout, distinguish those origins in that same narrow path instead of retrying by string alone.

**Why this scope.** It recovers factory and real callback failures without adding a generic Gate dependency to MirrorCPP, changing the `Error` layout, or regenerating every client binding. The SDK snapshot and local integration evidence are additive source APIs. Extending the SDK object's private storage or public evidence layout still requires rebuilding matching SDK/integration consumers and recording their identities; do not claim binary compatibility for precompiled consumers. The local Counter fixture may need only evidence plumbing in `counter_driver.cpp`; generated headers remain untouched. If actual callback coverage cannot be shown with the snapshot-before-dispose seam, introduce a typed trusted port error recorder at `CounterPort` before proposing any general generator change.

**Planned production/test files.** MirrorGate `sdk/cpp/include/mirrorgate/managed_worker.hpp`, `sdk/cpp/src/managed_worker.cpp`, `integrations/mirrorcpp/orchestration.hpp`, `integrations/mirrorcpp/orchestration.cpp`, `integrations/mirrorcpp/counter_driver.cpp`, `tests/cpp/sdk_test.cpp` or the existing managed-worker test owner, `tests/cpp/orchestration_receipt_test.cpp`, and a dedicated orchestration error fixture/test wired through `integrations/mirrorcpp/CMakeLists.txt` and `conformance/control-v1/run`. ## F7 — Haskell raw-byte bounded framing

**Scope and evidence.** `ModelMirros/src/Protocol/Transport/Core.hs:15` encodes JSON then calls `send` without a final-size check. TCP `ByteString.hGetLine` and stdio `ByteString.getLine` accumulate unbounded lines; TLS `src-tls/Protocol/Transport/Tls.hs:130` appends chunks without a uniform payload limit. TCP/stdio also collapse IO errors into empty bytes. This is source-confirmed only; no Haskell runtime was tested during the audit. Shared transport code is used by both reference client and server, so a fix affects both.

**Implementation contract.** Keep the existing `Transport` method signatures and line-payload abstraction; do not add LF twice or require callers to manually frame messages.

- Introduce one shared framing module, e.g. `src/Protocol/Transport/Framing.hs`, with `maxPayloadBytes = 65535`, final-payload validation and a bounded raw-byte LF scanner. Count bytes excluding only the terminating `0x0a`; validate before JSON parsing. Do not count Haskell `Text` characters, use an unbounded `hGetLine`, or decode each partial UTF-8 chunk.
- `Core.sendMsg` encodes to the final UTF-8 JSON bytes once, validates the final encoded payload, and then calls `send`. Enforce the same framing predicate in built-in `send` methods so direct `send` users cannot bypass it. A rejected outbound message must emit zero bytes; valid encoding gets exactly one LF. Preserve legal escaping and optional/null semantics.
- For TCP and stdio, use a shared bounded raw-handle reader that does not read past LF or discard bytes belonging to the next frame. Preserve exported `StdioTransport` construction if feasible: a bounded Handle reader avoids introducing mutable global stdin state. A simple bounded buffered-handle loop is acceptable initially; measure before optimizing. Any chunked implementation needs explicit retained suffix state, whose constructor/API impact must be reviewed.
- For TLS, reuse the pure scanner with the existing per-transport `IORef` remainder. Check the first LF position before interpreting the rest: several valid frames in one TLS chunk must not be mistaken for one oversized frame. Keep partial payload state at or below 65,535 bytes, plus a fixed bounded input chunk/suffix; never concatenate an unbounded remainder before checking. Account for the TLS library's receive-chunk bound and copy/retention behavior when documenting the memory limit.
- A 65,535-byte payload is accepted only when followed by LF; a 65,536th payload byte fails immediately, even without LF or EOF. EOF with zero pending bytes retains the established EOF behavior. EOF/read failure with a nonempty pending payload is an explicit truncated-frame failure. Blank-line handling follows C1's existing EOF sentinel; do not parse it as a JSON object. Preserve UTF-8 validation at the full-frame JSON decoder, including a multibyte sequence split across input chunks.
- Inbound oversize, invalid or truncated framing poisons the session and closes the relevant stream/connection or guarantees no further flow messages. Do not drain and resume on an oversized frame, parse its suffix as another message, silently return EOF for a partial frame, or send cleanup protocol messages on the damaged connection. This needs one explicit failure convention across Core and built-in transports: typed framing/IO failure at `recv`, converted to the existing `Either String` error at `recvMsg` if desired. Preserve source signatures rather than starting an unrelated public client error-model redesign. For stdio, terminate the dedicated protocol session and release its input endpoint; no process-global mutable framing state.
- A second final-size check in `recvMsg` is useful for custom/mock transports, but does not replace bounded reads in the real adapters. `MockTransport` remains a message queue rather than raw stream evidence.

**Planned files.** Add internal Framing module and test module. Update `src/Protocol/Transport/Core.hs`, `Tcp.hs`, `Stdio.hs`, `src-tls/Protocol/Transport/Tls.hs`; register the internal module in `ModelMirrors.cabal`; add `test/TransportFramingSpec.hs` and wire it into Cabal `other-modules` and `test/Main.hs`. Extend `test/TcpTransportSpec.hs`, `test/TlsTransportSpec.hs`, and process/pipe-backed stdio tests (new `StdioTransportSpec.hs` if clearer). Update transport docs/comments about EOF and bounds. If the selected exception convention needs `Protocol.Mirror` cleanup handling, limit that change to ensuring framing errors end only the affected session.

## D2 — retain exact POSIX 0600 as the common policy

**Decision recommended for implementation.** Keep current C27's normative predicate: `(mode & 07777) == 0600`. Align five permissive implementations; retain Rust as the existing regression reference. This avoids silently changing the published baseline and accepting executable/special-bit variants. It tightens existing behavior for owner-only `0400`/`0700`; `0400` is more restrictive than `0600` and neither owner-only mode alone proves key disclosure. State that compatibility cost explicitly. An owner-only policy is a defensible alternative, but it would be a deliberate contract revision plus Rust behavior change; it is not the selected fix.

| MirrorCPP | `src/detail/tls.cpp:57` `check_key_mode` | Extend `test/unit/tls_test.cpp:128`; validate before credential loading/connect. |
| MirrorRust | `src/transport.rs:345` already exact | Retain `tests/transport.rs:7` negative modes and 0600 credential-load control; no behavior change. |
| MirrorLean | `server-mode/native/mirrorlean_tls.c:78` `check_key_permissions` | Extend `server-mode/Test/ServerMode.lean:377` matrix and refresh corresponding comments/docs. |
| Mirrors built-in CLI | `Ffi/tls_shim.c:195` `key_perms_ok` | Extend `tools/TransportSpec.lean` (currently covers 0640) and relevant TLS/registry checks. Shared server/client helper should enforce the same explicit policy unless a documented role exception is adopted. |

The shared policy text in `Mirrors/Docs/client-implementation-guide.md:274` should explicitly say low 07777 bits must equal 0600, group/other, owner-execute and special bits are rejected, and the client validates rather than changes a key. Update neighboring client docs that currently describe only group/other access. Existing credential-generation scripts already normally create 0600 keys; verify fixture generation as part of the tests.

For every client, use disposable copies of a valid key; verify each requested mode was actually established. Accept 0600. Reject 0400, 0500, 0700, group/other variants such as 0644/0660 and special variants 01600/02600/04600 before opening a network connection. Assert unchanged bytes and unchanged mode after both acceptance/rejection: **never automatically chmod caller-owned key files**. A mode-0600 missing/invalid-credentials control must reach the ordinary credential loader to show that the permission predicate is the gate under test. Where filesystems cannot establish special bits, record an explicit platform limitation instead of treating an unexercised row as passed.

Keep the existing Windows exception: POSIX bits are not an ACL proof and ACL/platform behavior stays as documented. Include a Windows control showing absence of an artificial POSIX rejection; do not claim new Windows ACL enforcement. WSL Unix mode testing and native Windows ACL testing are separate profiles, especially on mounted Windows filesystems. These changes do not claim file-owner, symlink, ACL or TOCTOU guarantees.

For native C changes rebuild through the normal dependency graph on remote WSL and run the native rebuild gate there, including `bash tools/check-native-rebuild.sh` for Mirrors. All six mode-policy rows need fresh evidence before declaring D2 reconciled. Rollout note: callers using 0400 or executable/special-bit keys must explicitly prepare compliant copies or adjust their deployment configuration themselves.
